# MeshForge Stage 1: 외장형 MV-Adapter (파인튜닝 없는 멀티뷰 일관성)

> 목표: GPT-image(Codex CLI의 image_generation)를 **손대지 않고**, 바깥에서 거는 구조만으로
> 멀티뷰 일관성을 **측정 가능한 지표 기준 0.98 이상**까지 끌어올린다.

---

## 0. MV-Adapter가 실제로 하는 일 (논문 분해)

출처: [MV-Adapter 논문](https://arxiv.org/abs/2412.03632), [프로젝트 페이지](https://huanngzh.github.io/MV-Adapter-Page/)

| # | MV-Adapter 부품 | 하는 일 | 일관성이 생기는 이유 |
|---|---|---|---|
| A | **멀티뷰 어텐션** (self-attn 복제, 병렬 연결) | 뷰끼리 서로의 특징을 참조 | 같은 물체의 같은 부분을 뷰들이 "공유"함 |
| B | **Row-wise 어텐션** | 고도 0°, 정사영이면 같은 3D 점은 **모든 뷰에서 같은 행(y)** 에 있음 → 같은 행끼리만 참조 | 에피폴라 제약을 구조로 박아버림 |
| C | **이미지 크로스어텐션** | 레퍼런스 이미지를 같은 UNet에 t=0으로 통과시켜 뽑은 특징을 참조 | 정체성(디테일, 색)을 원본에서 복사 |
| D | **Condition Guider** | 카메라 raymap 또는 **position map / normal map** 을 conv 인코더로 넣음 | position map = "같은 색 = 같은 3D 점" 이라는 **뷰 간 대응 정보** |
| E | **Zero-init + 병렬 구조** | 원래 모델의 prior를 망가뜨리지 않음 | 품질은 원본 모델 그대로 유지 |
| F | **고정 카메라 배치** | 고도 0°, 방위각 {0, 45, 90, 180, 270, 315}, 정사영 | 문제를 단순화 |

핵심 인사이트: **일관성 = (뷰끼리 서로 보게 함) + (기하학 대응 정보를 줌) + (원본 prior 보존)**.

---

## 1. 외장화 매핑: 가중치 대신 "캔버스"를 조작한다

GPT-image는 내부 어텐션을 못 건드리지만, **한 장의 이미지 안에서는 모든 픽셀이 서로 어텐션한다.**
→ 여러 뷰를 **한 캔버스에 배치**하면 A(멀티뷰 어텐션)가 공짜로 생긴다.

| MV-Adapter | 외장형 대응 (MeshForge) |
|---|---|
| A 멀티뷰 어텐션 | **Turnaround Sheet**: 모든 뷰를 한 이미지 그리드에 동시 생성 |
| B Row-wise 어텐션 | **수평 정렬 레이아웃**: 뷰를 같은 행 높이에 배치 + 수평 가이드 라인. 생성 후 **행 프로파일 검사**로 강제 |
| C 이미지 크로스어텐션 | **In-context 앵커**: 레퍼런스(정면)를 시트의 첫 칸에 **이미 채워 넣고** 나머지 칸을 "완성"시킴 + 원본을 입력 이미지로 동시 첨부 |
| D Condition Guider | **Geometry Guide Sheet**: proxy 메쉬에서 렌더한 **NOCS position map + normal map** 시트를 가이드 이미지로 첨부. "같은 색 = 같은 점" |
| E Prior 보존 | 가이드는 **형태만**, 재질·디테일은 레퍼런스에서. 프롬프트는 짧고 고정. 새로 그리기보다 **완성/편집** 모드 |
| F 고정 카메라 | 정사영, 고도 0°, 방위각 고정 세트. 카메라 보정기로 잔여 오차 제거 |

그리고 MV-Adapter에 **없는** 것을 추가한다. 학습을 못 하니까 **검증 + 재생성 루프**로 보상:

- **G. 일관성 측정기**: 뷰 간 일관성을 숫자로 잰다 (아래 3장)
- **H. 패널 단위 수리**: 제일 안 맞는 뷰만 골라서 나머지 뷰를 문맥으로 주고 재생성
- **I. 생성 ↔ 재구성 사이클**: 생성 → Hull → 가이드 렌더 → 재생성. 돌 때마다 가이드가 정확해짐

## 2. 파이프라인

```
 레퍼런스 이미지
      │
      ▼
[S0] 정규화: 배경 제거, 무광 중성 조명으로 재생성(구워진 그림자 제거), 중앙 정렬
      │
      ▼
[S1] Pass-0 시트 생성 (가이드 없음)
     캔버스: 2x3 그리드, 정면 칸에 레퍼런스를 미리 붙여넣음
      │
      ▼
[S2] 분할 + 정규화: 칸 자르기 → 마스크 → 공통 스케일/기준선 맞추기
      │
      ▼
[S3] 카메라 보정 + 투표제 Visual Hull  ──►  proxy 메쉬 v0
      │
      ▼
[S4] Guide 렌더: proxy에서 NOCS position / normal / 실루엣 시트 렌더
      │
      ▼
[S5] Pass-k 시트 생성: 레퍼런스 + 이전 시트 + Guide 시트 첨부
      │
      ▼
[S6] 일관성 측정 ──► 점수 < 0.98 ?
      │                  ├─ 전체가 나쁨 → S3로 (proxy 갱신, 사이클)
      │                  └─ 특정 칸만 나쁨 → [S7] 패널 수리 → S6
      ▼
[S8] 고해상도 패스: 칸 하나씩 업스케일/디테일 강화
     (실루엣 마스크 고정, 이웃 뷰를 문맥으로 첨부)
      │
      ▼
 → Stage 2 (Relight + 광도 스테레오)로 전달
```

### 카메라 규약 (MV-Adapter F를 따름)
- **정사영**, 고도 0°, 방위각 6개: `0, 45, 90, 180, 270, 315` (정면/대각/측면/후면)
- 모든 칸에서 물체의 **바닥선과 꼭대기선이 같은 y**
- 배경: 단색 중성 회색(#808080), 그림자 없음

### 왜 2x3 그리드인가
- 1536x1024 캔버스 → 칸당 512x512. 일관성은 한 캔버스라 좋지만 해상도가 낮음
- 그래서 S8에서 **칸별 고해상도 패스**를 따로 돈다 (일관성은 시트에서, 해상도는 패스에서)

## 3. "일관성 98"의 정의 (측정 가능해야 목표가 된다)

정사영 + 고도 0° 조건에서는 **정답 없이도 검사 가능한 기하학 법칙**이 있다. 이게 핵심.

| 지표 | 정의 | 왜 성립하나 | 목표 |
|---|---|---|---|
| **M1 대칭 실루엣 IoU** | view(θ)와 좌우반전 view(θ+180°)의 실루엣 IoU | 정사영에서 반대편 실루엣은 **정확히 거울상** | ≥ 0.98 |
| **M2 행 범위 일치** | 각 행 y에서 물체가 있는지 여부가 모든 뷰에서 같은 비율 | 고도 0° 정사영에서 3D 점의 y는 뷰와 무관 | ≥ 0.98 |
| **M3 Hull 재투영 IoU** | 모든 뷰로 Hull을 깎은 뒤 각 뷰로 재투영한 실루엣 vs 원래 실루엣 | 서로 모순이 없으면 Hull이 각 실루엣을 그대로 재현 | ≥ 0.98 (최악 뷰 기준) |
| **M4 광도 재투영 오차** | proxy 깊이로 뷰 i를 뷰 j로 워핑, 겹치는 영역의 LPIPS / 색차 | 같은 표면은 같은 색이어야 함 | LPIPS ≤ 0.10 |
| **M5 정체성 점수** | 정면 칸 vs 원본 레퍼런스 (DINO 특징 코사인) | 원본을 잃지 않았는지 | ≥ 0.95 |

**종합 점수** = min(M1, M2, M3) 을 주 지표로 쓰고, M4·M5는 통과/실패 조건으로 쓴다.
평균이 아니라 **최솟값**인 이유: Hull은 교집합이라 **제일 나쁜 뷰 하나가 결과를 망친다** (1회차의 부스러짐 원인).

---

## 4. 수리 전략 (S7)

1. M3를 뷰별로 계산 → IoU 제일 낮은 칸 = 범인
2. 범인 칸을 비운 시트 + 나머지 칸 + 해당 칸의 guide(proxy 렌더)를 첨부해서 **그 칸만 다시 채우게** 함
3. 새 칸이 점수를 올리면 채택, 아니면 폐기 (최대 N회)
4. M1이 나쁜 쌍(θ, θ+180°)은 서로의 거울상 실루엣을 가이드로 줘서 맞춤

---

## 5. 1회차 대비 개선점

| 1회차 문제 | 원인 추정 | 2회차 대응 |
|---|---|---|
| 부스러짐, 구멍 | Hull 교집합에서 한 뷰의 얇은 실루엣이 이김 | M3 뷰별 검사 + 패널 수리 + 투표제 카빙 |
| 뷰 경계 찢어짐 | 뷰별 노멀 적분 후 이어붙임 | Stage 3에서 전역 노멀 최적화 (별도 문서) |
| 일관성 "느낌상 좋음" | 수치 지표 없음 | M1~M5 자동 측정, 매 실행마다 리포트 |

## 6. 구현 순서 (Stage 1)

1. `mf/sheet.py`: 그리드 레이아웃, 칸 자르기, 앵커 붙여넣기
2. `mf/imagegen.py`: Codex CLI `image_generation` 호출 래퍼 (입력 이미지 첨부, 출력 수집, 캐시)
3. `mf/segment.py`: 배경 제거, 마스크, 기준선 정규화
4. `mf/metrics.py`: M1, M2, M3 (GPU 없이 numpy로 가능)
5. `mf/hull.py`: 투표제 Visual Hull + marching cubes
6. `mf/guide.py`: proxy 메쉬에서 NOCS / normal 시트 렌더 (CPU 래스터라이저)
7. `mf/loop.py`: S1~S7 사이클 오케스트레이션
8. `bench/`: 정답 3D 모델을 렌더한 시트로 측정기 자체 검증

지표(4)를 생성(2)보다 먼저 검증한다. 자가 없으면 98을 못 잰다.
